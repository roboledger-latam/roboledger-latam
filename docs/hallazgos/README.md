# Hallazgos

Lo que alguien del equipo descubrió y el resto tiene que saber: un límite de una herramienta, un riesgo, un dato del jurado, un problema en el diseño.

- **Algo que aprendimos** → un archivo en esta carpeta.
- **Algo que alguien tiene que hacer** → un Issue de GitHub asignado a una persona, linkeado desde el hallazgo.

## Cómo escribir uno

1. Creá un archivo con el nombre `AAAA-MM-DD-tema-corto.md`, por ejemplo `2026-10-04-licencia-dataset.md`.
2. Copiá la plantilla de abajo y completala.
3. Agregalo al índice de esta página.
4. Abrí un PR como con cualquier otro cambio.

## Plantilla

```markdown
# Título que describe el hallazgo

- **Fecha:** AAAA-MM-DD
- **Autor:** nombre
- **Estado:** abierto / resuelto / descartado

## Qué encontré

Una o dos frases.

## Fuente o evidencia

Link, captura, comando o documento donde se puede comprobar.

## Qué implica para el proyecto

Qué cambia, qué riesgo trae o qué decisión habilita.

## Qué propongo

Acción concreta. Si requiere trabajo, link al Issue.
```
